Architecture Overview

짜장면 vs 짬뽕 투표 API

FastAPI + SQLite 단일 프로세스로 중복 투표 원자적 차단과 재시작 후 데이터 영속성을 보장하는 최소 운영형 백엔드. Docker 이미지 하나를 Fly.io 단일 Machine에 올리고, DB 파일은 영구 볼륨 /data에 둔다.

Python 3.12 FastAPI 0.116 Uvicorn 0.35 · workers=1 SQLite · WAL Docker Fly.io (nrt) GitHub Actions

01시스템 구성

클라이언트 → Fly 엣지(HTTPS 강제) → 단일 Machine 안의 Uvicorn 프로세스 → 같은 프로세스 메모리의 VoteStore → 마운트된 볼륨 위 SQLite 파일. 네트워크 홉이 하나뿐이라 정합성 경계가 SQLite 파일 하나로 수렴한다.

애플리케이션 런타임 영속 저장소 플랫폼 / CI

02코드 레이어 — app/main.py 한 파일

계층이 얇다. Pydantic 모델이 경계에서 검증하고, 라우트 함수는 위임만 하며, VoteStore가 SQLite 접근을 전부 감싼다. DB 경로가 create_app(database_path) 인자로 주입되므로 테스트는 tmp_path로 완전히 격리된다.

03요청 흐름과 동시성 — 중복 투표가 새지 않는 이유

애플리케이션 레벨에서 "이미 투표했나?"를 조회하지 않는다. 조회 후 삽입은 두 문장 사이에 경쟁 구간이 생기지만, 여기서는 곧바로 INSERT를 던지고 SQLite PRIMARY KEY 제약이 거부한 것을 409로 번역한다. 유일성 판정이 DB 한 지점에서 원자적으로 끝난다.

테스트 통과

고유 voterId 100건 동시

ThreadPool 20 workers · 100건 전부 201, 집계 유실 0건.

테스트 통과

동일 voterId 20건 동시

정확히 1건만 201, 나머지 19건 409. 레이스 없음.

테스트 통과

재시작 후 영속성

같은 DB 파일로 앱을 다시 만들어도 이전 표와 중복 규칙이 유지됨.

04API 계약

엔드포인트요청응답
POST /api/vote {"choice":"jajang|jjamppong","voterId":"user-123"} 201 {"status":"accepted"}
409 이미 투표한 voterId
422 choice 오류 · voterId 누락/공백/129자 이상
GET /api/result 없음 200 {"jajang":n,"jjamppong":n,"total":n} — VoteResult로 응답 스키마 고정
GET /health 없음 200 {"status":"ok"} — DB에 SELECT 1을 실제로 던진 뒤 응답 (프로세스 생존만 보는 얕은 체크가 아님)

05빌드 · 배포 파이프라인

같은 Dockerfile이 로컬(compose)과 운영(Fly)에서 그대로 쓰인다. 차이는 /data에 무엇을 마운트하느냐뿐 — Docker named volume이냐 Fly Volume이냐.

06설계 판단과 그 대가

선택

조회 없이 INSERT → 409 번역

"먼저 확인하고 넣기"는 두 문장 사이에 경쟁 구간이 생긴다. 유일성 판정을 PK 제약 한 곳에 몰아 애플리케이션 락 없이 원자성을 얻었다.

선택

DB 경로 주입형 app factory

create_app(path) 덕분에 테스트가 tmp_path로 완전히 격리되고, 같은 경로로 두 번 만들어 프로세스 재시작까지 모사할 수 있다.

선택

SQLite + 단일 볼륨

40분 과제 범위에서 분산 DB 없이 정합성·영속성을 동시에 만족하는 가장 적은 구성요소.

대가

수평 확장 불가

DB 파일이 한 볼륨에 묶여 Machine을 늘릴 수 없고 workers=1도 같은 이유. 규모가 커지면 PostgreSQL의 UNIQUE 제약으로 같은 규칙을 옮기는 것이 다음 수순.

대가

auto_stop · min=0 콜드 스타트

유휴 시 Machine이 정지해 첫 요청에 기동 지연이 붙는다. 비용 대신 지연을 택한 설정.

보조 도구

표준 라이브러리 smoke script

scripts/smoke_test.py는 의존성 없이 임의의 Public URL에 대해 health · 201 · 409 · 집계 증가를 한 번에 판정한다.
